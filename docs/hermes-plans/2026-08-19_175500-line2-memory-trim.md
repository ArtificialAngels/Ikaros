**Objective:** 修复审计发现的所有 P0 问题——这些是"用户可见的故障"或"生产致命"。

**Task 2.0.1: 修 PEP 701 嵌套同引号 f-string**（致命）
- 文件：`core/memory_v5/tools/memory_tool.py:148`
- 问题：嵌套同引号 f-string 在 Python 3.11 编译失败（PEP 701 要 3.12+），导致 tools/* 11 个模块 import 失败，**v5_memory_store / v5_memory_search / v5_self_model_get 等 48 个 MCP 工具全挂**
- 修复：把内层 f-string 改成普通字符串 + .format() 或拆开
- 验证：`cd E:/Ikaros && python -c "from memory_v5.tools.memory_tool import *"` 不能报错
- **风险**：低（语法修复，不动语义）
- 修复后跑全套测试 + 手工调一个 MCP 工具确认活着

**Task 2.0.2: embedding circuit breaker**（生产致命）
- 文件：`core/memory_v5/extensions/embedding.py` 或 `services/`（具体位置看代码）
- 问题：bge-m3 down 时 retrieve 2-20s（10s timeout × 2 = 20s）
- 修复：加熔断器——连续 3 次 timeout 后短路 30s，期间直接返空向量 + log
- 验证：模拟 :8587 不可达，retrieve 应 < 100ms
- **风险**：中（短路策略可能影响召回，需 tunable）

**Task 2.0.3: context_anchor 静默 except 加 logger**（数据风险）
- 文件：`core/memory_v5/context_anchor.py` L52/63/74/94/99/119（6 处）
- 问题：`except Exception: pass`，情境锚永远缺信号无告警
- 修复：每处加 `logger.warning(f"context_anchor failed: {e}")`（至少记录异常）
- **风险**：极低（只加日志）

**Task 2.0.4: entity_graph WAL fallback 修复**（数据风险）
- 文件：`core/memory_v5/entity_graph.py` eg_conn() L117/123/131/135

- **风险**：低（暴露真实错误而不是隐藏）

**Task 2.0.5: PROMOTE_* 常量收口**（数据一致）

### Task 2.4: 注释分类规则文档

**Objective:** 定义什么注释留、什么删。

**保留（功能性）：**
- 解释 **WHY** 的：设计决策、gotcha、调用契约
- 标注来源：原文引用、issue 链接、commit hash
- 解释**接口不变量**：必须 / 永远 / 不要 / 这是约定

**删除（非功能性）：**
- 解释 **WHAT** 的（代码已自明）
- 历史口语（"v3 之前叫 xxx，现在改叫 yyy"）
- 临时 TODO 已完成（"// TODO: fix later" 但已 fix）
- 重复 docstring（函数上 + 类上 + 模块上 + 文件头都重复一遍）
- 废话注释（"// Now we do the thing"）

**Step 1:** 写 `/tmp/v5-comment-classification.md`，给哥哥过目。
