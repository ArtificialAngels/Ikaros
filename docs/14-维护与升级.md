## 升级便携运行时(`portable-python/` + `runtime/`)

```bat
bin\setup-portable.bat
```

会自动用 aria2c 多线程下载:
- `portable-python/` — 嵌入式 Python 3.12.10
- `runtime/` — llama.cpp Windows 二进制 + DLL
- `runtime/cuda/12.4/` — CUDA 12.4 运行时(默认)

下载完成后**第一次启动前** 跑一次 `bin\hermes-firstrun.bat` 验证。

## 升级上游 hermes-agent(NousResearch)

> **不要** 直接 `git clone` 覆盖 `hermes-agent/`。我们走 **selective sync** 流程——
> 只挑我们需要的升级点，绝不把上游的全量差异一股脑塞进来。

### 1. 准备:克隆上游到 `upstream/hermes-agent/` (不入 git)

```bat
python bin\hermes-upstream-sync.py pull hermes-agent
python bin\hermes-upstream-sync.py status
python bin\hermes-upstream-sync.py tag-check
```

确认 pinned tag 还在本地(我们当前锁的是 v0.16.0,见 AGENTS.md "Phase 11 锁定")。

### 2. 看上游变化

```bat
python bin\hermes-upstream-sync.py diff hermes-agent
python bin\hermes-upstream-sync.py report
```

`report` 会生成 `docs\upstream-candidates.md` —— 列出所有 v0.16.0 之后的上游 commit。

### 3. 评估每个候选 commit

对每个候选,问 3 件事:
- 这 commit 影响我们**直接 import** 的代码吗?(看 `hermes-agent/agent/*.py`、`hermes-agent/hermes_cli/*.py` 等)
- 我们有**对应二次开发**吗?(看 `modules/`、`bridge/`、`hermes/`)
- 升级会不会**破坏**我们的 sitecustomize / adapter?(检查 `bridge/sitecustomize.py`)

如果 3 个答案都是"是/有/不确定",**先做 dry-run pick**,不直接落盘。

### 4. 干跑 pick

```bat
:: 把上游某个文件 copy 到我们的一个临时验证目录(不直接落到真实位置)
python bin\hermes-upstream-sync.py pick hermes-agent agent\tts_provider.py _tmp_dryrun\tts_provider.py
```

### 5. 对比、测试、决定

- 用 IDE / diff 工具看新文件 vs `hermes-agent/agent/tts_provider.py`(我们当前锁定的)
- 在临时目录里跑一遍冒烟测试,确认 import / API 没炸
- 通过 → 走 `git mv _tmp_dryrun\tts_provider.py hermes-agent\agent\tts_provider.py` 然后 commit
- 不通过 → 删 `_tmp_dryrun\`,继续看下一个候选

### 6. 升级 pinned 版本号

确认所有选中的升级都 merge 之后,把 `bin\hermes-upstream-sync.py` 里 `UPSTREAMS["hermes-agent"]["our_pinned"]` 从 `v0.16.0` 改为新 tag,commit。

### 7. 清理

```bat
rm -rf upstream\hermes-agent      :: 下次需要再 pull,不留大体积在仓库
```

### 提交给上游(可选)

如果我们做的修复**通用且有价值**:
1. 把修复从我们的 `modules/` / `bridge/` 抽出来,变成对上游有用的 patch
2. 到 https://github.com/NousResearch/hermes-agent/issues 提 PR
3. 上游合并后,我们的 pinned 版本可以 bump,自然带回来

## 分支管理规范

我们只有一个 `main` 分支承担"可发布稳定版"角色。需要和上游打交道时,**用临时分支 + 一次性合并**:

| 分支 | 角色 | 创建时机 |
|------|------|---------|
| `main` | 唯一长期分支,任何时候都应可启动 | — |
| `upstream-tracking/<name>` | 跟踪某个上游 release tag 的临时分支 | 跑 `bin\hermes-upstream-sync.py pull <name>` 后,如需深入验证 |
| `feature/<name>` | 任何新功能或修复,完工后 squash merge 回 main | 开始一项新工作时 |

### 一次性 merge 模式(推荐)

不开长期 `develop` / `release` 分支,所有改动走 feature branch + PR(或直接 squash commit):

```bat
:: 1. 拉一个 feature 分支
git checkout -b feature/tts-edge-zh-voice

:: 2. 在分支上做改动(改 modules/ / bridge/ / docs/ 等)
::    ... 改 ...

:: 3. 跑测试,确认 OK
python tests\hermes\test_hermes.py

:: 4. 合并回 main(squash,保留单一可读 commit)
git checkout main
git merge --squash feature/tts-edge-zh-voice
git commit -m "feat(tts): default edge voice to zh-CN-XiaoxiaoNeural"
git branch -d feature/tts-edge-zh-voice
```

### 上游 sync 分支的特殊情况

如果上游某个 commit 触发了我们想 cherry-pick 的多个文件,**先开 `upstream-tracking/<name>`**:

```bat
git checkout -b upstream-tracking/v0.17.0

:: 在这个分支上做:clone 上游、diff、挑文件、跑测试
python bin\hermes-upstream-sync.py pull hermes-agent
python bin\hermes-upstream-sync.py diff hermes-agent
:: ... 选 commit,逐个 pick 到模块化适配位置 ...

:: 测试通过后,合并回 main(commit 历史可能多 commit,但保留清晰)
git checkout main
git merge --no-ff upstream-tracking/v0.17.0 -m "upstream: cherry-pick from v0.17.0 — see AGENTS.md §5"
git branch -d upstream-tracking/v0.17.0
```

然后把 `bin\hermes-upstream-sync.py` 里 `UPSTREAMS["hermes-agent"]["our_pinned"]` 从旧 tag 改为新 tag,commit。

## 添加新模型

1. 下载 GGUF 模型文件(从 HuggingFace / ModelScope / hf-mirror)
2. 放到 `data\models/` 目录
3. 重启 `bin\hermes-all.bat`,router 模式自动发现
4. (可选)编辑 `data\models\router-preset.ini` 给它单独配 NGL / ctx

### 推荐模型(按性能排序)

| 模型 | 大小 | 显存需求 | 适用 |
|---|---|---|---|
| Qwen2.5-1.5B-Instruct-Q4_K_M | ~1 GB | 2 GB VRAM | 极低配 / 快速 |
| Qwen2.5-3B-Instruct-Q4_K_M | ~2 GB | 4 GB VRAM | 低配 / 快速 |
| Qwen2.5-7B-Instruct-Q4_K_M | ~4.4 GB | 6 GB VRAM | 通用对话 |
| Llama-3.1-8B-Instruct-Q4_K_M | ~4.7 GB | 6 GB VRAM | 通用对话 |
| Qwen3-30B-A3B (MoE) | ~18 GB | 8 GB VRAM(部分 offload) | 强推理 |

### 模型 NGL 自动 / 手动

- **自动**:`bin\hermes-all.bat` 启动时根据 VRAM 自动算每个模型的 NGL。
- **手动**:`data\models\router-preset.ini` 给特定模型写死 NGL / ctx / temperature。

## 备份什么

| 必须备份 | 重要 | 备份价值不大 |
|---|---|---|
| `.env`(API 密钥) | `data\models\`(几十 GB,看容量) | `__pycache__/` |
| `data\memory\`(长期记忆) | `data\skills\`(用户安装 skill) | `data\logs\` |
| `data\knowledge\`(KB 索引) | `data\hermes-agent\`(webui 状态/会话) | `.opencode/tmp/` |
| `data\webui\`(webui 数据库) | `data\kanban\` / `data\crons\` / `data\sessions\` | `.hermes-root` |
| `config\hermes.yaml` | | `portable-python\`(可重下) |
| `data\models\router-preset.ini` | | `runtime\`(可重下) |

## 完全重置

1. **关闭 Hermes 和 LLM 服务**:`bin\hermes-stop.bat`
2. **备份**你想保留的数据(见上表)
3. **删除运行时数据**:
   ```bat
   rd /S /Q data\memory
   rd /S /Q data\knowledge
   rd /S /Q data\logs
   rd /S /Q data\hermes-agent
   rd /S /Q data\webui
   rd /S /Q data\kanban
   rd /S /Q data\crons
   rd /S /Q data\sessions
   REM 不要删 data\models\(模型权重)
   ```
4. **重新启动**:`bin\hermes-all.bat` — 自动重新初始化

## 移动到别的 U 盘

```bat
:: 1. 关闭所有
bin\hermes-stop.bat

:: 2. 整个项目文件夹拷到新 U 盘(随便盘符)

:: 3. 删除 HERMES_ROOT 缓存(强制重新解析路径)
del .hermes-root

:: 4. 启动
bin\hermes-all.bat
```

> `bin\hermes-root.py` 会扫描所有盘符找 `Ikaros/portable-python/python.exe`,自动确定新根路径。

## 升级 Git hooks

`.githooks/pre-commit` 是 **版本化** 的(在 git 里跟踪),`bin\install-git-hooks.bat` 一次性把它指向 `core.hooksPath`。`git pull` 之后 hook 自动更新,不需要重装。
