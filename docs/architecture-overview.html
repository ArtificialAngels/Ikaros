数据流 一次对话怎么走

1
用户在 Neko 前端 :48911（React+Avatar）发起对话
2
对话树 :48920 双模式（ikaros/hermes）默认走 Hermes Bridge :8650 → 纯净 gateway :8642（完整 tools/skills 循环 + V5 记忆注入）
3
gateway 不可达 → 降级本地 DeepSeek 直连 + 只读工具回路；本地 :8080 仅按需懒加载
4
逐轮记忆轻写进 V5（core/memory_v5/data/v5/）；后台 reflect 流水线提炼事实/情感/自我模型
5
V5 经 memory_api / v5_* MCP 工具 暴露检索；⚠️ 2026-08-14 审计：记忆写入→对话树推送链（旧 push_to_conversation_tree）已随 hermes_provider 删除，当前无实现
6
ThirdSpace 同步 bin/sync-thirdspace-v5.py 把 thought 写入 data/thirdspace-vault/（双轨知识库）

边界与约定 关键架构决策

⚠️ neko 保持独立： apps/neko 完整保留，不引入对 memory_v5 的代码依赖，不搬移 neko 内部 memory/ 模块。迁移脚本与方案文档已删除。
✅ v5.db 契约保留： 包已重命名 v5→memory_v5，但 DB 文件名 v5.db、40 个 v5_* MCP 工具名是对外契约，不改。
⚠️ v5-memory 独立仓库： E:\v5-memory 是从 core/memory_v5 抽离的开源插件版（无运行数据），两份手动同步，改主工程不影响开源版。
✅ 严禁裸跑 llama-server： 缺 CUDA DLL 会 SIGSEGV，一律走看门狗/控制面板启动。
