# 15 — 故障排查与救命命令

## 出问题去哪查

| 现象 | 第一看 | 备选 |
|---|---|---|
| launcher.bat 打不开 | 控制台输出错误信息 | `bin\hermes-doctor.bat` 诊断 |
| LLM 服务起不来 | `hermes/data/logs/` 下最新日志 | 手动 `runtime\llama-server.exe -m data\models\xxx.gguf` 测试 |
| Web UI 进不去 | `http://localhost:7860/health` 是否返回 OK | 检查 7860 端口是否被占用 |
| 对话不响应 | LLM 服务是否在 8080 端口运行 | `curl http://localhost:8080/v1/models` |
| 云端 LLM 失败 | `.env` 文件 API Key 是否正确 | 检查网络 / 代理设置 |
| 模型找不到 | `data/models/` 下是否有 .gguf 文件 | `launcher.bat` 重新扫描 |
| 显存不足（OOM） | 选小模型（Qwen2.5-3B） | `data\models\router-preset.ini` 给每个模型单独的 `n-gpu-layers`，35B 默认 16 层 GPU + CPU offload |
| GPU 加速不生效 | NVIDIA 驱动版本 | `bin\gpu-detect.bat` |
| API 密钥泄漏 | 检查是否误提交到 git | `git log --oneline --all -- .env` |

## 救命命令

```bat
:: 诊断扫描
bin\hermes-doctor.bat

:: 首次运行自检
bin\hermes-firstrun.bat

:: 强制结束所有 LLM 进程
taskkill /F /IM llama-server.exe

:: 强制结束所有 Python
taskkill /F /IM python.exe

:: 清日志
del /Q hermes\data\logs\*.log

:: 重置 Agent 数据（保留模型）
rd /S /Q hermes\data\memory
rd /S /Q hermes\data\knowledge
rd /S /Q hermes\data\cache

:: 干净启动 LLM 服务（手动）
runtime\llama-server.exe -m data\models\Qwen2.5-3B-Instruct-Q4_K_M.gguf --port 8080 -ngl 0

:: 测试 LLM 是否在线
curl http://localhost:8080/v1/models

:: 测试 Web UI 是否在线
curl http://localhost:7860/health

:: 查看端口占用
netstat -ano | findstr :8080
netstat -ano | findstr :7860
```

## 常见问题快速修复

### Q: "No module named 'xxx'"
```bat
portable-python\python.exe -m pip install xxx
```

### Q: llama-server.exe 闪退
```bat
:: 手动运行看报错
runtime\llama-server.exe -m data\models\Qwen2.5-3B-Instruct-Q4_K_M.gguf --port 8080
```

### Q: Web UI 页面空白
按 F12 打开浏览器控制台看 JS 报错。确认 `chat_ui.py` 未被修改。

### Q: 云端 API 调用超时
检查 `.env` 中 API Key 有效性。检查代理设置（Clash / V2Ray 是否在跑）。
