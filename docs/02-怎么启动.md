# 02 — 怎么启动

> 项目根路径自动解析(`bin\hermes-root.py`),跨 U 盘盘符自适应(`E:\` / `F:\` / `G:\` 都行)。
> 第一次运行建议先跑 `bin\hermes-firstrun.bat` 做 GPU 检测和环境自愈。

## 推荐:一键启动全部

```
双击 bin\hermes-all.bat
```

自动按拓扑顺序启动所有模块:

1. `env_bootstrap` — GPU 检测 / 路径校验
2. `llm_engine` — llama-server router 模式(:8080)
3. `bridge` — FastAPI(:7860)
4. `webui` — Hermes Web UI(:8648,**主入口**)
5. 浏览器自动打开 `http://localhost:8648/`
6. `bin\hermes-model-run.bat` 弹出 llama-server 实时日志窗口

`hermes-all.bat` 内部实际是调 `bin\hermes-supervisor.py`,后者读 `modules/*/module.json` 的 `depends_on` 字段做拓扑排序。

## 启动器速查表

| 用途 | 命令 | 说明 |
|------|------|------|
| **一键启动全部(推荐)** | `bin\hermes-all.bat` | 拓扑顺序启动所有模块 |
| 停止全部 | `bin\hermes-stop.bat` | 优雅停止(从 supervisor 反向发停) |
| 首次运行 / GPU 检测 | `bin\hermes-firstrun.bat` | GPU 检测 + 环境自愈 |
| 健康检查 | `bin\hermes-health.ps1` | TCP / `/v1/models` / `/v1/completions` 三层探测 |
| 控制台(切换模型 / 启停服务) | `bin\hermes-console.bat` | 交互式 shell,`Switch-Model` 等命令 |
| 实时 LLM 日志 | `bin\hermes-model-run.bat` | tail `llm-server.log` + 颜色高亮 |
| 模型管理 CLI | `bin\hermes-models.py list\|info\|download` | 列表 / 详情 / 下载 |
| 路径诊断 | `bin\hermes-root.bat resolve` | 打印当前 `HERMES_ROOT` |
| 注册 git hooks | `bin\install-git-hooks.bat` | 一次性安装 pre-commit CRLF 检查 |

## 仅启动 Web UI(LLM 服务已运行)

```bat
REM 启动 LLM 服务一次
bin\hermes-firstrun.bat
bin\hermes-all.bat
REM ... 或者单独启动 llm_engine:
modules\llm_engine\start.ps1
modules\bridge\start.ps1
modules\webui\start.ps1
```

Web UI 在 `:8648`,浏览器打开即可。Bridge 在 `:7860`,LLM 在 `:8080`,**它们缺一不可**。

## CLI 控制台 — `hermes-console.bat`

交互式 shell,常用命令:

```powershell
PS> Switch-Model Qwen2.5-7B-Instruct-Q4_K_M.gguf   # 切换 LLM
PS> Status                                         # 查看所有模块状态
PS> Restart-Module webui                           # 重启单个模块
PS> Tail-Logs llm                                  # tail llama-server 日志
PS> Help                                           # 所有命令
```

## 全新 Windows 电脑上(刚 git clone 完)

```bat
:: 1. 拉仓库
git clone https://github.com/ArtificialAngels/hermes-agent.git
cd hermes-agent

:: 2. 安装便携运行时(portable-python + runtime + 默认 CUDA)
bin\setup-portable.bat

:: 3. 注册 git hooks(阻止 LF-only .bat 提交)
bin\install-git-hooks.bat

:: 4. 首次运行 — GPU 检测 + 环境自愈
bin\hermes-firstrun.bat

:: 5. 下载 GGUF 模型(自己挑)
bin\hermes-models.py download Qwen/Qwen2.5-7B-Instruct-GGUF
REM 或者手动放到 data\models\

:: 6. 一键启动
bin\hermes-all.bat
```

## 想只用云端(不下载模型)

`.env`(从 `.env.example` 复制):

```bash
OPENAI_API_KEY=sk-...
```

然后 `bin\hermes-all.bat` 会自动用云端,断网时 fallback 到本地(没有本地模型就会报错)。

## 配置文件解读(`config/hermes.yaml`)

```yaml
llm:
  router:
    strategy: fallback_chain       # 失败自动切换
    primary: cloud                 # 首选云端
    fallback_order: [cloud, local]

  cloud:                           # 云端 LLM 列表
    - name: openai
      provider: openai
      base_url: https://api.openai.com/v1
      models:
        default: gpt-4o
        fast: gpt-4o-mini

  local:                           # 本地 LLM(llama-server router 模式)
    provider: openai
    base_url: http://127.0.0.1:8080/v1
    models:
      default: qwen2.5-7b-instruct
```

**关键参数**:
- `strategy: fallback_chain` — 云端挂了自动切本地
- `primary: cloud` — 有网优先用云端的强模型
- `base_url: http://127.0.0.1:8080/v1` — 本地 LLM 默认端口 8080(llama-server router)

## 启动顺序(技术细节)

```
hermes-all.bat
  └── bin\hermes-supervisor.py start
        ├── 读 modules/*/module.json, 拓扑排序 by depends_on
        ├── 启动 env_bootstrap    (GPU detect, no port)
        ├── 启动 llm_engine       (depends_on: env_bootstrap, port: 8080)
        ├── 启动 bridge           (depends_on: llm_engine,    port: 7860)
        └── 启动 webui            (depends_on: bridge,         port: 8648)
```

每个模块等 `health.ps1` 探测返回 OK 才启动下一个。失败会回滚已启动的。

## 停止顺序

`bin\hermes-stop.bat` 是启动的反向:webui → bridge → llm_engine → env_bootstrap,优雅发 SIGTERM,5 秒后 SIGKILL。
