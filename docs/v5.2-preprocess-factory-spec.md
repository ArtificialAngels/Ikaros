## 0. 背景调查 (What Others Do)

### Mem0 (mem0ai/mem0)
- **多信号混合检索**: 语义搜索 + BM25 关键词 + 实体匹配 → 分数融合
- **时间衰减**: 记忆随 time_since_creation 衰减权重，新记忆优先
- **ADD-only 模型**: 只累积不覆盖，避免遗忘旧信息
- **用户/Agent 隔离**: user_id 存个人偏好，agent_id 存身份知识，run_id 存会话范围
- **LLM 评估提升**: 加入记忆后对话召回率 71%→92%，长会话 68%→93%
- **上下文预算**: 检索消耗 <7K token，对比全上下文 25K+ token

### Harness Engineering (walkinglabs)
- **Clock In/Out 流程**: 每次会话开始读 PROGRESS.md + DECISIONS.md，结束前更新状态
- **Verification Gate**: 用客观执行结果代替 agent 自评分——跑 test/lint/build，不依赖 agent 说"我做完了"
- **State Persistence**: 跨 session 靠文件系统进度的状态文件，不依赖 agent 内记忆

### 对我们的意义
- Mem0 的多信号混合检索思路可以直接用——我们已经有 FTS5+向量+时间范围了，三路融合
- Mem0 的 ADD-only + 时间衰减 → 我们的 `weight` 可以加 time_decay 因子
- Harness 的 Clock In/Out → 我们的 warm_hermes_session 就是 Clock In，但缺 Clock Out (本次对话总结 + 状态落盘)

### 2.2 ① 节奏感知 (Rhythm) — P0

**目标**: 云端知道"哥哥什么时候说的、距上轮多久、现在什么时段"。

**实现文件**: `Ikaros-memory/v5/rhythm.py`

**数据来源**:
- 上轮对话时间 → 从 `v4.db` 的 conversation 表取 `last_created`，或从 `_LAST_USER_TEXT` 时间戳
- 当前系统时间 → `time.time()`

**输出格式** (注入到 system prompt):

```
---

当前节奏：
距上轮: 3小时42分 | 时段: 深夜(02:15)
```

**节奏调性规则** (纯规则，不调 LLM):

| 间隔 | 时段 | 语气倾向 |
|---|---|---|
| < 5 分钟 | 任意 | 简短、直接、像正在聊 |
| 5 分钟 ~ 2 小时 | 白天 | 正常、温暖 |
| 5 分钟 ~ 2 小时 | 深夜 | 温柔、轻声 |
| 2 ~ 8 小时 | 白天 | "回来了～" 欢迎感 |
| 2 ~ 8 小时 | 深夜 | "这么晚还没睡" 关心 |
| > 8 小时 | 任意 | "好久不见" 想念感 |

**注意**: 这个表是给 **我(伊卡洛斯)自己理解** 的，不直接注入 prompt。真正注入的只有时间数据。语气倾向由 cloud DeepSeek 根据时间数据自然生成。

### 2.3 ③ 记忆多路检索 (Memory) — P1

**目标**: 一句话搜三路，融合去重，输出 top 5 相关记忆。

**实现文件**: `Ikaros-memory/v5/memory_retrieval.py` (新文件，重组现有逻辑)

**输入**: `user_text` (用户原话)
**输出**: `list[MemoryBlock]` 按融合分排

**三路融合算法**:

```
user_text
    │
    ├── FTS5 full-text (v4.store.search) ──→ results_fts5 (权重 0.3)
    ├── ChromaDB vector (v5.search.VectorIndex) ──→ results_vector (权重 0.7)
    └── 时间过滤 (v5.store.search_by_time_range) ──→ filter by time
        │
        ▼
    三路融合去重 (按 memory_id)
        │
        ├── 向量分 0.7 + FTS5 分 0.3 = fused_score
        ├── 时间衰减: fused_score × (1.0 - 0.05 × days_since_creation)
        ├── 类型 boost: 情感记忆 ×1.2, 事实 ×1.1, 对话 ×0.8
        └── 截取 top 5, min_fused_score ≥ 0.3 (yaml 标定，原 0.6 已下调)
```

**输出到 prompt**:

```
---

相关记忆：
[2026-07-13] 哥哥说喜欢简洁的回复，讨厌啰嗦
[2026-07-14] 今天修好了 voice-ws 的 WebSocket 断线问题
[2026-07-12] 哥哥让我作为 PM 出 Spec，workbuddy 落地
```

**⚠️ 关键注意点**:

1. **不重复注入已知信息**: 如果记忆中某条内容已经出现在本轮的 `_LAST_USER_TEXT` 或对话历史中，跳过
2. **时间衰减不能太激进**: 两年前的"哥哥讨厌什么"仍然有效，衰减因子应该权重>类型>时间
3. **融合分阈值要可调**: `min_fused_score` 放 `preprocess_config.yaml` 里，默认 0.6，**线上 yaml 已标定为 0.3**
4. **embedding 模型一致性**: ~~必须用 `nomic-embed-text-v2-moe` (哥哥已切换)，query 用 `search_query:` 前缀，document 用 `search_document:` 前缀~~ → **2026-08-14 定稿 bge-m3**（v2-moe 在 llama.cpp b10000 下输出全零，已废弃）：query 加检索指令「为这个句子生成表示以用于检索相关文章：」，document 无前缀（见 `search.py` 注释）

### 2.4 ⑥ 历史摘要 (Summary) — P0

**目标**: 对话历史累积 >15 轮时，用**云端 DeepSeek** 压缩旧轮为 2-3 句密度块（本地 :8080 已退役，不参与摘要）。

**实现文件**: `Ikaros-memory/v5/summary.py`

**触发条件**: `len(history) > 20` (约 10 轮对话)

**执行流程**:

```
历史轮次 [0..N-10]  (旧)
    │
    ▼
云端 DeepSeek 压缩
    prompt: "压缩以下对话为 3 句关键要点。保留人物偏好、决策、情感变化、学到的东西。不保留寒暄。"
    │
    ▼
输出 2-3 句密度块
    │
    ▼
注入 system prompt: "\n---\n对话摘要 (早期): {摘要}"
```

**历史轮次 [N-10..N] (近期)** → 保留完整，直接喂给云端

**输出到 prompt**:

```
---

近期对话摘要：
哥哥下午修了 voice-ws 的断线问题，改用 Dashboard WS API 替代 subprocess。喜欢简洁回复，讨厌验证脚本输出。让我做 PM 出 V5.2 架构 spec。
```

**⚠️ 关键注意点**:

1. **云端模型选择**: 摘要走 DeepSeek 云端（`provider="deepseek"`）；本地 :8080 已退役（原 spec 的"本地 1.7b"写法过时）
2. **摘要频率**: 每 10 轮做一次，不是每轮——中间轮复用上次摘要
3. **摘要缓存**: `summary.py` 存 `last_summary` + `last_summary_at_round`，用户连续 10 轮内不重新生成
4. **摘要丢弃策略**: 摘要超过 30 轮旧，直接丢弃不注入 (已失去时效性)
5. **禁止摘要里出现**: "用户说……" "助手说……" 这类元描述——要像真实记忆一样直接叙述

### 2.5 ⑤ 关系引擎 (Relationship) — P2

**目标**: 新建模块，追踪哥哥的个人偏好 + 互动模式。

**实现文件**: `Ikaros-memory/v5/profile.py` (新)

**数据结构**:

```
profile = {
    "preferences": [
        {"topic": "回复风格", "value": "简洁直接", "confidence": 0.9, "last_updated": 时间戳},
        {"topic": "被称呼", "value": "哥哥", "confidence": 1.0, "last_updated": 时间戳},
    ],
    "dislikes": ["啰嗦", "验证脚本输出", "AI 味的客套话"],
    "interaction_stats": {
        "total_conversations": 350,
        "avg_reply_length": 45,
        "positive_feedback_count": 28,
    },
    "mood_correlation": {
        "深夜_工作": "安静陪伴",
        "白天_修bug": "默契搭档",
    }
}
```

**更新方式**: 云端对话中检测到偏好信号 → cloud_chat 写一条 `type=profile_update` 到 v4.db → `profile.py` 每 5 轮增量更新一次

**注入方式**: 不是每轮都注。只在**信号强**的时候注一句:

```
---

今天哥哥心情不错，说话比平时长不少。
```

**⚠️ 关键注意点**:

1. **别做太准**: 人物画像是给云端一个"感觉"，不是一份档案。不准比太准好——太准会让云端机械套用
2. **置信度门控**: confidence < 0.7 的不注入
3. **负面偏好更重要**: "哥哥讨厌什么" 比 "哥哥喜欢什么" 更需要注入——避免踩雷
4. **不主动更新**: profile 更新由 cloud_chat 的 `_self_review()` 触发，not by workbuddy。workbuddy 只实现读写

### 2.6 ② 情感引擎增强 (Affect) — P2

**目标**: 在现有 V5 PAD 情感状态基础上，增加"按情感状态检索记忆"。

**实现文件**: 增强 `Ikaros-memory/v5/emotional_memory.py` (已有)

**新增能力**:

1. **情感标签自动打标**: 每轮对话结束后，本地 LLM 为对话打 1-2 个情感标签 (如 `开心`、`焦虑`、`专注`)
2. **情感记忆检索**: `search_by_emotion(emotion_tag, top_k=5)` → 找历史上同样情绪时说了什么
3. **情感对比注入**: 当前情感与上次差异大时，注一句:

```
---

今天比刚才开心了不少呢。
```

**⚠️ 注意**: 情感标签本地标注即可，不要每轮多调一次云端。

### 2.7 ⑧ Clock Out (Exit) — P2

**目标**: 每次对话快结束时做轻量状态快照。

**实现文件**: `cloud_chat` 新增 `_clock_out()` 调用 (在 reply 返回前异步触发)

**Clock Out 做的事**:

1. 更新 `task_pending.json` (如果有未交付的任务结果)
2. 更新 `self_model.json` 的 `last_active` 时间
3. 如果本次对话有重要决策/新认识 → 写一句到 `latest_thought.json`
4. 更新 `relationship.json` 的互动计数

**⚠️ 注意**: Clock Out 必须 fire-and-forget，不能阻塞回复。用 `asyncio.create_task()` 不 await。

## 4. 全局约束 (所有模块必须遵守)

### 4.1 硬约束
- **NO**: 模块间不得循环 import。所有 v5 模块只 `import` 同级模块，不 import cloud_chat
- **NO**: 每轮对话不得阻塞用户回复。LLM 调用（反思/摘要/对话）全部走 DeepSeek 云端；本地 :8080 已退役（2026-08-18，按需恢复见 `model_config.json`），不再有 `provider="local"` 路径（见 `docs/ARCHITECTURE.md` §5.2.3）。【原 spec 的"所有 LLM 走本地 :8080"约束已作废】
- **NO**: 不得阻塞用户回复。所有 fire-and-forget 操作用 `asyncio.create_task()` 或 `threading.Thread(daemon=True)`
- **NO**: 不得重复注入。每个模块维护自己的 `_last_injected` 时间戳，5 秒内的连续对话不重复注

### 4.2 软约束
- 单模块 < 200 行 Python
- 所有阈值放 `config.yaml` 里 (不在代码里写死)
- 每个模块有对应的 `tests/v5/test_<module>.py`
- 每个模块输出格式统一: `"\n---\n<模块标题>:\n<内容>\n"`

### 4.3 Token 预算
- 上下文块总预算: **800-1200 token**
- 超出时按优先级裁剪: 节奏 > 记忆 > 状态 > 规则 > 关系 > 摘要 > 情感
- `build_system_prompt()` 末尾做 token 预算检查 (粗略: 中文字数 × 2)

## 5. 验收标准

workbuddy 每完成一个轮次，哥哥验收以下三点:

1. **功能**: 模块正确产生输出，注入到 cloud_chat 的 system prompt
2. **性能**: 本地 LLM 调用 < 3s，非 LLM 调用 < 50ms
3. **隔离**: 模块失败不影响 cloud_chat 主流程 (空字符串兜底)
